fix: v1.3.2 修复 wb2 测试发现的 P0/P1 问题

## P0 修复
- `/tab-org/status` 和 `/tab-org/migrate` 恒 500：根因是用 `request.app.state.gateway`
  而非闭包变量 `gw`，且遗留记录缺 `tab_org_mode` 字段时缺少异常处理。
- 修复后两个 API 均正常返回，P2 迁移功能和 P3 分流预警恢复可用。

## P1 修复
- WebUI「保存设置」用 POST `/settings`（405），改为 PUT（后端仅接受 PUT）。
- 前端 `/tab-org/status` 失败时静默吞错，改为显式显示红色错误提示卡片，
  避免用户误以为「没有可迁移的 flow」。
- P4 混合模式 `target_tab` 参数在 MCP 工具中未暴露：
  - `autoflow_deploy_raw` 增加 `target_tab` 参数（文档说明+示例）
  - `propose_raw` 增加 `target_tab` 参数并写入提案 content
  - `deploy_proposal` 从提案 content 读取 `target_tab`（调用方未显式指定时）

## 增强
- `get_migration_status` 增加 mixed_count 统计，对非 dict 类型的 flow meta 做健壮性处理。
- 迁移 API 失败时返回 traceback 最后 500 字符，便于排障。

## 测试验证
- wb2 测试报告：9 个用例中 0 个完全通过，P2/P3 被 P0 后端崩溃整体阻断。
- 本次修复针对测试报告中的 iss_6e19d7ae48、iss_ecd2d1148f、iss_4b128ace58、iss_8635e27853。
- 撤回精度机制已被 wb2 实测通过（trimmed_tab 分支行为正确）。
