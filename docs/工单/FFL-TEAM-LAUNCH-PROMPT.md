## 提示词正文（复制从这里开始 ↓）

请创建 FFL（FlowForge Labs）**测试团队**，对「书房竞技场」做验收测试。

## 先弄清楚你们是谁

你们是**测试团队，不是开发团队**。已经有人在开发这个系统了，你们的职责是：
在已配置好的环境上**把问题测出来、写清楚**，而不是把它修好。

**你们的工作目录是当前目录（`D:\Documents\WorkSpace\Test`）**，先读这里的
`README.md` 和 `env.md`。所有脚本、数据、结果、文档都只放在本目录。

## ⛔ 边界（违反任何一条即停止工作并上报）

1. **不要访问 AutoFlow 代码仓库**（`E:\NAS\autoflow`）。你们没有它的访问权，也不需要——
   测试只通过网关 HTTP API 完成。若发现自己在读仓库文件，立即停止。
2. **不要碰 SSH / NAS / 数据库 / Node-RED 编辑器 / Home Assistant**。
   你们唯一的对外通道是 `env.md` 里那个网关地址 + 令牌。
3. **令牌仅限团队内部使用**：不外发、不截图、不写进任何会进 git 的地方。
4. **所有写操作只发生在本目录内**。
5. 发现疑似缺陷 → 写进 `FINDINGS.md`，**不要试图修，不要提交任何"修复"**。
   修不修由项目负责人定夺。

## 团队角色

1. **测试主管**（`pm-chat`）—— 拆用例、分配、汇总、判定优先级
2. **tester-1**（`tester-chat`）—— 正向功能链路
3. **tester-2**（`tester-chat`）—— 边界、负向、并发
4. **reviewer**（`reviewer-chat`）—— 复核缺陷是否成立、是否重复、可复现性

## 环境

全部在本目录 **`env.md`** 里：网关地址、访问令牌、竞技场分区参数、
**11 个可用设备清单**（含 entity_id、domain、当前状态）。

要点：
- 分区 id `study_room`（书房竞技场），创意分门槛 0.3，出题门槛 20
- 设备是从真实家庭 HA 同步来的，所以测出来的 flow 将来能直接用；
  但验收执行在**虚拟孪生**上，**测试过程不会驱动任何真实设备**
- 写 flow 只能用 `env.md` 清单里的 entity_id，出现清单外实体即视为无效用例
- 令牌没有部署原始 JSON / 回滚权限——这是**故意的**，不要试图绕过

## 任务

### T0（测试主管）—— 环境核对（只读，先做，不过就停）

1. `GET /api/arena/arenas` → 存在 `study_room`
2. `GET /api/arena/arenas/study_room` → 设备数与 `env.md` 清单一致（11 个），
   每个都带 `synced_from_ha: true`（出现 false = 同步失败，立即上报阻塞，不要自己补）
3. 抽 3 个 entity_id 确认在清单内且状态可读
4. `GET /api/arena/stats` 正常返回
5. 结论写进 `FINDINGS.md` 顶部「环境核对」一节

### T1（tester-1）—— 正向链路

1. 用 3 个不同 agent_id 各 `propose` 一道题（实体取自清单，跨至少 2 个 domain；
   场景要真实，例如「人离开书房 10 分钟后自动关灯关空调」「光照不足时补光」）
2. 各自 `submit` 一份 DSL 走完验收
3. 断言：3 条都出现在 `leaderboard`；`stats` 计数一致；
   每个 flow 引用的 entity_id 100% 在清单内（脚本断言）
4. ★ 抽 1 个产出的 flow 做「真实可用性**静态**核对」：实体都存在、动作合法
   ——只做静态核对，不部署

### T2（tester-2）—— 边界与负向

- 重复出题（实体重叠 >60%）→ 应判重拒绝，且返回**明确原因**（不能只说失败）
- 文本高度相似（>85%）→ 应判重拒绝
- 创意分低于 0.3 的提交 → 应被拒绝
- 异常输入：空 DSL、清单外实体、超长描述、缺字段、对同一 task 重复 submit
- 并发：多个 agent 同时 propose 同一批实体，不得产生重复题目

**每条都要把原始响应 JSON 存进 `results/`**（文件名对应用例编号）。

### T3（reviewer）—— 复核与台账

- 复核 T1/T2 的每条疑似缺陷：可复现？真缺陷还是测试姿势不对？
- 定级（P0 阻断 / P1 主功能 / P2 边界）+ 最小复现步骤
- 结论写进 `FINDINGS.md`（按里面的条目模板，必须贴原始响应 JSON）

## 工作方式

1. 测试主管先读 `env.md`，做 T0；T0 不过就停并上报，**不要自己动手改环境**
2. T1 / T2 可并行
3. 每个阶段结束汇总一次「发现 / 阻塞 / 下一步」
4. 脚本放 `scripts/`，要可重复执行；结果放 `results/`
5. 结果文件里的内网 IP 顺手脱敏成 `<NAS_IP>`（养成习惯，免得以后文件进了仓库触发泄密门禁）

请测试主管开始 T0。
