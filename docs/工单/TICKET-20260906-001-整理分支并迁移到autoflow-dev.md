## 需求描述

### 背景
AutoFlow 主仓库 (`lidicn/AutoFlow`) 目前有 12+ 个开发分支，这些是 FFL 团队（原 Hermes 团队）在协作模式建立前推送的。为了规范协作流程，需要：
1. 整理现有分支，分类评估价值
2. 高价值分支合并到 master
3. 其余分支迁移到新的 `autoflow-dev` 开发仓库
4. 清理主仓库，保持干净稳定

### 目标
- 主仓库只保留 master/main + 必要的长期分支
- 所有开发工作迁移到 autoflow-dev 仓库
- 高价值修复不丢失，合并到 master

### 范围
- 包含：现有 12+ 分支的整理、评估、合并、迁移
- 不包含：新功能开发、架构变更

---

## 验收标准

- [ ] **分支清单**：列出所有现有分支，包含分支名、最后提交时间、提交数、改动内容摘要
- [ ] **分类评估**：每个分支标记为「合并到 master」/「迁移到 autoflow-dev」/「关闭」
- [ ] **高价值合并**：标记为「合并」的分支已提交 PR 并合并到 master（需 dw 审查）
- [ ] **迁移完成**：标记为「迁移」的分支已推送到 autoflow-dev 仓库
- [ ] **主仓库清理**：主仓库已删除迁移和关闭的分支，只保留 master/main
- [ ] **文档记录**：整理结果记录在 `docs/协作/分支整理记录.md`

---

## 技术要求

- 合并前必须 rebase 到最新 master，解决冲突
- 合并的代码必须通过 dw 审查
- 迁移的分支保持完整历史，不压缩提交
- 关闭的分支需要说明关闭原因
