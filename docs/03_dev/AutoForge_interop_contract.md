# AutoForge ↔ AutoFlow 交接契约（Contract-First）

> 出品：AutoFlow 网关（lidicn / WorkBuddy）
> 日期：2026-09-29
> 状态：**契约先行，当前不实现**（DCD 议题三裁定：A 不排期 + B 先定接口契约不实现；v4.0.0 生态共存才落地）
> 受体基准：AutoFlow 冻结实现 `4b703f5`（契约以 AutoFlow 侧为准，AutoForge 适配）
> 关联：`docs/ROADMAP_DCD版_v2.2.md` 议题三 / v4.0.0；`docs/03_dev/MA_interop_design.md`（同类型跨项目契约先例）

---

## 0. 为什么先写契约

AutoForge 仍在快速迭代（已交 codebuddy，设计冻结中）。按 DCD「等成熟度」裁定，实现时机未到；
但**接口边界可以先钉死**——避免两侧各自演进后再对接时出现「语义对不齐、各自以为对方会处理」的
返工。本契约只定边界，**不包含任何实现承诺**。

---

## 1. 定位与硬边界（不可协商）

| | AutoForge | AutoFlow |
|---|---|---|
| 角色 | **creator**：agent 创作工厂 | **gatekeeper**：人主导的安全部署 / 验证 / 回滚网关 |
| 产出 | 场景意图 → DSL / flow 制品 | 对制品做校验、重放验证、快照、回滚 |
| 谁批准 | **不批准**（agent 不得自我批准） | **人批准**（批准/升格只在 WebUI） |
| 是否写生产 | 绝不直连 NR 写生产 | 唯一写入通道，且受防御层约束 |

> 铁律：agent 不自我批准、不自我创作上线物。AutoForge 可以「造」，但**不能让它造的东西自己上线**。

---

## 2. 非重叠声明（双向负面清单）

**AutoForge 不做**（越界即违规）：
- ❌ 不经 AutoFlow 直接部署到任何 NR 实例；
- ❌ 自行判定「验证通过」并放行（验证结论以 AutoFlow 闸门为准）；
- ❌ 持有 HA / NR 生产凭证（凭证只留在网关）；
- ❌ 复制 AutoFlow 的验证语义（避免两套「绿灯」定义漂移）。

**AutoFlow 不做**（避免重复造轮子）：
- ❌ 创作 / 生成场景内容或 DSL 正文（那是 AutoForge 的活）；
- ❌ 猜测 agent 的创作意图并擅自改写（IR 不得静默改写）；
- ❌ 承担长期健康度 / 创造力职能（归 MA）。

---

## 3. 交接格式边界（导出物 → 受体）

**交接物 = 一份「可被 AutoFlow 独立取回并验证」的制品**，而不是「一段要 AutoFlow 猜的文本」。

| 维度 | 约定 |
|---|---|
| **形态** | 优先 **ref 寻址的制品**（AutoFlow 已有 `DraftStore` ref 暂存 + 制品总线统一 ref 寻址）；次选完整 flow JSON。**禁止**让 AutoFlow 从对话上下文里还原制品。 |
| **受体模型** | 交接物必须能映射进 AutoFlow 的**可验证 / 可回滚模型**：即能过 `verify_flow`（与 `deploy_raw` 同源质量闸）并能被 `#16` 快照/回滚覆盖。 |
| **只读语义** | 交接给 AutoFlow 的验证动作必须是**只读**的（不写 NR）；部署才是写动作，且必须走人批准。 |
| **失败语义** | 制品未过闸 = **block**，不是 warn。AutoForge 不得把「AutoFlow 说 block」降级解释为「可以上线」。 |
| **凭据** | 制品内绝不内嵌 HA/NR 凭据；涉及凭证的一律由 AutoFlow 在部署期注入（如 HA server 由网关注入）。 |

**交接物的最小可接受检查项**（AutoForge 侧导出前自检，但不替代 AutoFlow 闸门）：
① 结构合法（能被 AutoFlow schema 校验解析）；② 实体引用明确（不靠 AutoFlow 猜域）；
③ 含触发源与可达动作链；④ 无硬编码凭据。

---

## 4. 验证与回滚归 AutoFlow（唯一口径）

- 验证语义、闸门、防假绿、`c4_replay_semantics`（已终裁 fail_closed）**全部以 AutoFlow 实现为唯一真相源**；
- AutoForge 若做「预览/自检」，须明确标注为**非权威**，并指向 AutoFlow 的最终结论；
- 回滚以 AutoFlow 的整实例快照（`#16`）为准，AutoForge 不得自行实现回滚通道。

---

## 5. 既有共享契约铁律（沿用，勿重开辩论）

以 AutoFlow 冻结实现 `4b703f5` 为基准：
1. 降级空串**绝不清零**；
2. 注册表抓取失败静默返空 → 必须判空 + REST 兜底；
3. 各能力组**独立 try**，不得一崩全崩；
4. 学习闭环只沉淀 **high 置信 + 单候选**；
5. `binding` 用独立 map；
6. **IR 不得静默改写**；
7. 长期健康度归 MA（不在本契约范围）。

命名（已冻结）：对外 **AutoForge**，子命令 `forge build/run/sim`，包名 `autoforge`，模块前缀 `af_*`。
不叫 AutoFlow Next。

---

## 6. 实现触发条件（v4.0.0）

同时满足才启动实现，否则本契约保持「只定不实现」：
1. AutoForge 设计冻结且接口稳定（不再频繁变更导出形态）；
2. 用户明确需要 AutoForge 产物进 AutoFlow 这条路径；
3. 两侧各落一份本契约（或等价文档）并互相认可。

**当前状态**：条件 1 未满足 → **不排期**。本文件仅作为边界留档，供未来对接时校验是否漂移。

---

## 7. 未决问题（留待实现前裁决）

- 导出形态首选 **ref** 还是 **完整 JSON**（取决于 AutoForge 侧是否常驻可寻址存储）；
- 若 AutoForge 产物含 AutoFlow 未建模的能力（如自定义子流程），降级策略是 block 还是 warn+人工确认；
- 交接是否需要携带「创作意图 / 场景描述」元信息供人批准时展示（当前 AutoFlow 批准卡只给意图+验证结果+影响设备）。
