## 二、v2.0.0 开发任务分解

### Sprint 1（9/5 - 9/10）：基线对齐 + 核心实验特性

#### 任务 1.1 — 多 Agent 身份管理（P0，2 天）
- **负责人**：backend-dev
- **描述**：扩展 API Key 模型，支持多个 Agent 同时连接，每个 Agent 拥有独立 API Key、独立的授权范围和 Token 配额
- **涉及模块**：`api_keys.py`、`webui.py`（Agents 面板）、`token_stats.py`
- **验收标准**：
  - 1. 可同时创建 ≥3 个 Agent，各自独立 API Key
  - 2. 每个 Agent 有独立的授权 tab 列表
  - 3. Token 消耗按 Agent 独立统计，不混淆
  - 4. 吊销单个 Agent 不影响其他 Agent
  - 5. WebUI 显示 Agent 列表，区分不同 Agent 的消耗
- **前置依赖**：无
- **测试用例**：tester 编写 5 条核心用例

#### 任务 1.3 — 一键回滚（P1，2 天）
- **负责人**：backend-dev
- **描述**：部署失败时一键回滚到上一版本快照。利用已有的 snapshots 机制，增加部署失败自动回滚 + 手动回滚接口
- **涉及模块**：`gateway.py`（deploy 逻辑）、新增 `rollback_api.py`、`webui.py`
- **验收标准**：
  - 1. 部署失败时自动回滚到部署前快照
  - 2. `/api/core/rollback` 支持手动指定回滚版本
  - 3. WebUI 显示部署历史，可点击「回滚」按钮
  - 4. 回滚后验证 NR 侧状态一致
  - 5. 回滚操作记录到审计日志
- **前置依赖**：无（与 1.1 并行）
- **测试用例**：tester 编写 5 条核心用例

#### 任务 1.2 — Flow 版本对比（P1，1.5 天）
- **负责人**：frontend-dev
- **描述**：部署前显示新旧 flow 的 diff，可视化变更（新增节点、删除节点、修改节点）
- **涉及模块**：`webui.py`（部署确认弹窗）、新增 `diff.js`
- **验收标准**：
  - 1. 部署前弹窗显示新旧 flow 的结构化 diff
  - 2. 新增节点标绿色，删除节点标红色，修改节点标黄色
  - 3. 支持折叠/展开 diff 详情
  - 4. 小变更（≤3 节点）折叠显示，大变更默认展开
  - 5. 移动端可正常查看
- **前置依赖**：无（与 1.1/1.3 并行）
- **测试用例**：tester 编写 3 条核心用例

### Sprint 2（9/11 - 9/14）：增强特性 + 回归测试

#### 任务 1.4 — 实时日志流（P2，2 天）
- **负责人**：backend-dev（SSE 后端）+ frontend-dev（前端消费）
- **描述**：WebUI 实时显示网关日志，方便调试。使用 Server-Sent Events（SSE）实现实时推送
- **涉及模块**：新增 `log_stream.py`（后端 SSE）、`webui.py`（前端日志面板）
- **验收标准**：
  - 1. `/api/core/logs/stream` 返回 SSE 事件流
  - 2. WebUI 底部日志面板实时更新，显示最近 100 条日志
  - 3. 支持按级别过滤（INFO/WARN/ERROR）
  - 4. 连接断开时前端自动重连（≤3 秒）
  - 5. 不影响其他接口的响应性能
- **前置依赖**：Sprint 1 任务完成后
- **测试用例**：tester 编写 3 条核心用例

#### 任务 1.5 — 暗色模式（P3，1 天）
- **负责人**：frontend-dev
- **描述**：WebUI 支持暗色主题，跟随系统设置或手动切换
- **涉及模块**：CSS 变量重构、新增 `theme.css`
- **验收标准**：
  - 1. 默认跟随系统设置（light/dark）
  - 2. 设置页可手动切换主题
  - 3. 所有页面、弹窗、图表均适配暗色模式
  - 4. 主题切换不刷新页面
  - 5. 持久化到 localStorage
- **前置依赖**：无（可独立开发）
- **测试用例**：tester 编写 2 条核心用例

#### 集中回归测试（9/14 - 9/15）
- **负责人**：tester
- **范围**：v2.0.0 全功能回归 + 从主版本吸收的功能验证
- **验收标准**：
  - 1. 所有 P0/P1 功能通过测试
  - 2. API Key 管理、模板库、Token 统计（继承自 v1.5.x）正常
  - 3. nr_client.py --gateway 模式正常
  - 4. 测试报告提交到 docs/04_test/
- **前置依赖**：所有开发任务完成

## 四、风险矩阵

| 风险 | 级别 | 影响 | 应对方案 |
|------|------|------|---------|
| 多 Agent 与现有单 Agent 架构冲突 | 🔴 高 | 1.1 延期，阻塞 1.4/集中测试 | 先做兼容层，不改核心数据模型；必要时降级为「Agent 列表+备注」 |
| 一键回滚与 NR 状态不一致 | 🟡 中 | 1.3 延期 | 回滚后增加 NR 状态验证步骤，不一致时明确告警而非静默失败 |
| 暗色模式改造范围过大 | 🟡 中 | 1.5 延期 | 先覆盖核心页面，次要页面可后续补齐 |
| 实时日志流性能问题 | 🟡 中 | 1.4 延期 | 限制日志缓冲长度（100 条），过滤低频日志，前端 3 秒重连而非无限重连 |
| Sprint 间依赖未满足 | 🟡 中 | 整体延期 | PM 每日检查前置依赖，必要时调整任务顺序 |
