# 测试工单：v1.4.0 部署授权码（Trusted Agent Auto-Deploy）P0-P2

**版本**: v1.4.0 (commit a5f1ec4, tag v1.4.0)
**测试者**: wb2
**测试环境**: 远端测试机
**测试日期**: 2026-09-03
**优先级**: P0（核心新功能，需全面验证）

---

## 测试范围

本次测试覆盖 v1.4.0 新增的「部署授权码」完整功能：
- 授权码创建/验证/吊销
- 授权码自动部署（MCP 传 deploy_token，无需人工确认）
- 全量快照 + 全量回滚
- 增量快照 + 选择性回滚
- 审计日志
- 操作频率限制 + 资源配额
- 危险操作二次确认
- 使用统计面板
- fail-safe 回退机制（授权码无效时回退人工审批）

---

## 前置条件

1. AutoFlow 已更新到 v1.4.0（在线更新或 git pull）
2. Node-RED 运行正常，至少有 2 个 tab（如「客厅」「卧室」）
3. MCP 连接正常，agent 身份码有效
4. WebUI 可正常访问

---

## 测试用例

### P0-1: 授权码创建与显示

**步骤**:
1. 打开 WebUI → 管理 → 授权码
2. 点击「创建授权码」
3. 填写：名称="测试授权码"，目标 tab="客厅"，有效期=1小时，权限=部署，节点阈值=50，最大节点=500，最大flow=20，频率=10
4. 点击「创建」

**预期**:
- [ ] 创建成功弹窗显示授权码明文（格式 dt_xxxxxxxx）
- [ ] 弹窗提示"请立即复制并保存，此授权码只显示一次"
- [ ] 关闭弹窗后，列表中出现该授权码，状态为「有效」
- [ ] 列表中不显示授权码明文（只显示名称、目标tab、统计）

---

### P0-2: 授权码列表与状态显示

**步骤**:
1. 创建 2 个授权码（一个有效，一个稍后吊销）
2. 查看授权码列表

**预期**:
- [ ] 列表按创建时间倒序排列
- [ ] 每个授权码显示：名称、状态徽章（有效/已吊销/已过期）、目标tab、权限、创建时间、到期时间
- [ ] 使用统计显示：部署次数、修改次数、撤回次数、节点数、失败次数
- [ ] 有效授权码有「吊销」按钮，已吊销的没有

---

### P0-3: 授权码自动部署（MCP 路径）

**步骤**:
1. 创建一个授权码，目标 tab="客厅"，权限=部署
2. 通过 MCP 调用 `autoflow_deploy_raw`，传入一个简单 flow（如 inject→debug），同时传入 `deploy_token="dt_xxx"`
3. 观察返回结果

**预期**:
- [ ] 返回结果中 `auto_deploy.ok=true`，`auto_deploy.deployed=true`
- [ ] 返回结果中有 `flow_id` 和 `label`
- [ ] Node-RED「客厅」tab 中出现该 flow 的节点
- [ ] **不需要**在 WebUI 提案页面手动点击部署
- [ ] 授权码列表中该授权码的「部署次数」+1，「节点数」+对应数量

---

### P0-4: 授权码自动部署（DSL 路径）

**步骤**:
1. 通过 MCP 调用 `autoflow_propose_dsl`，传入一个简单 DSL，同时传入 `deploy_token="dt_xxx"`
2. 观察返回结果

**预期**:
- [ ] 闸门通过时，返回结果中 `auto_deploy.ok=true`
- [ ] Node-RED 目标 tab 中出现该 flow
- [ ] 不需要人工确认

---

### P0-5: 授权码吊销

**步骤**:
1. 创建一个授权码
2. 点击「吊销」按钮
3. 确认吊销
4. 用该授权码尝试自动部署

**预期**:
- [ ] 吊销后状态变为「已吊销」
- [ ] 吊销按钮消失
- [ ] 用已吊销授权码自动部署时，`auto_deploy.ok=false`，`auto_deploy.fallback="manual"`
- [ ] 提案正常落档，等待人工审批（不拒绝部署）

---

### P0-6: 授权前全量快照

**步骤**:
1. 创建授权码前，记录目标 tab 当前节点数
2. 创建授权码
3. 用授权码自动部署一个 flow
4. 查看该授权码的快照列表

**预期**:
- [ ] 快照列表中有「自动部署前快照」
- [ ] 快照类型为「增量」，记录了部署前的节点数
- [ ] 快照时间在部署时间之前

---

### P0-7: 全量回滚

**步骤**:
1. 用授权码自动部署一个 flow 到目标 tab
2. 记录部署后目标 tab 的节点数
3. 打开该授权码的快照列表
4. 找到部署前的快照，点击「回滚到此」
5. 确认回滚

**预期**:
- [ ] 回滚成功提示
- [ ] 目标 tab 恢复到部署前的状态（节点数减少）
- [ ] 快照列表中新增一条「回滚前快照」（防止误回滚）
- [ ] 回滚后可以再次回滚到之前的状态

---

### P0-8: 审计日志

**步骤**:
1. 用授权码执行几次自动部署（成功和失败各一次）
2. 点击该授权码的「日志」按钮

**预期**:
- [ ] 日志按时间倒序排列
- [ ] 每条日志显示：操作类型、时间、Agent ID、Flow 名称、节点数、成功/失败状态
- [ ] 失败的日志显示错误信息
- [ ] 日志数量与实际操作次数一致

---

### P1-1: 操作频率限制

**步骤**:
1. 创建一个授权码，频率限制=2次/分钟
2. 在 1 分钟内连续调用 3 次自动部署

**预期**:
- [ ] 前 2 次成功
- [ ] 第 3 次 `auto_deploy.ok=false`，错误信息包含"操作频率超限"
- [ ] 等待 1 分钟后可以再次部署

---

### P1-2: 资源配额 - 节点数

**步骤**:
1. 创建一个授权码，最大节点数=10
2. 用该授权码部署一个 8 节点的 flow（成功）
3. 再部署一个 5 节点的 flow

**预期**:
- [ ] 第一次部署成功（8 ≤ 10）
- [ ] 第二次部署失败，错误信息包含"节点数配额已满"
- [ ] 已用节点数显示为 8/10

---

### P1-3: 资源配额 - flow 数

**步骤**:
1. 创建一个授权码，最大 flow 数=2
2. 用该授权码部署 2 个 flow（成功）
3. 再部署第 3 个 flow

**预期**:
- [ ] 前 2 次成功
- [ ] 第 3 次失败，错误信息包含"flow 数配额已满"

---

### P1-4: 危险操作二次确认

**步骤**:
1. 点击任意授权码的「吊销」按钮
2. 不确认，取消
3. 再次点击，确认
4. 点击任意快照的「回滚到此」
5. 不确认，取消
6. 再次点击，确认

**预期**:
- [ ] 吊销前弹出确认对话框
- [ ] 取消后授权码仍然有效
- [ ] 确认后授权码被吊销
- [ ] 回滚前弹出确认对话框
- [ ] 取消后 tab 状态不变
- [ ] 确认后执行回滚

---

### P1-5: 节点数超阈值回退人工审批

**步骤**:
1. 创建一个授权码，节点阈值=10
2. 用该授权码部署一个 15 节点的 flow

**预期**:
- [ ] `auto_deploy.ok=false`，`auto_deploy.fallback="manual"`
- [ ] 错误信息包含"节点数超过阈值"
- [ ] 提案正常落档，等待人工审批

---

### P2-1: 使用统计面板

**步骤**:
1. 用授权码执行多次操作（部署、失败）
2. 查看授权码列表

**预期**:
- [ ] 部署次数准确
- [ ] 节点数准确（累计）
- [ ] 失败次数准确，失败次数 > 0 时显示红色
- [ ] 最后使用时间更新

---

### P2-2: 目标 tab 绑定限制

**步骤**:
1. 创建一个授权码，目标 tab="客厅"
2. MCP 调用时传入 `target_tab="卧室"`（与授权码绑定的 tab 不同）
3. 观察部署结果

**预期**:
- [ ] 授权码绑定的目标 tab 优先级最高，flow 部署到「客厅」而非「卧室」
- [ ] 返回结果中 `auto_deploy.target_tab="客厅"`

---

### P2-3: 授权码过期

**步骤**:
1. 创建一个授权码，有效期=0.01小时（约36秒）
2. 等待过期
3. 用该授权码尝试自动部署

**预期**:
- [ ] 过期后列表状态变为「已过期」
- [ ] 用过期授权码部署时 `auto_deploy.ok=false`，错误信息包含"已过期"
- [ ] 提案正常落档，等待人工审批

---

### P2-4: 授权码无效回退人工审批（fail-safe）

**步骤**:
1. 用一个不存在的授权码 `dt_nonexistent` 尝试自动部署
2. 观察结果

**预期**:
- [ ] `auto_deploy.ok=false`，`auto_deploy.fallback="manual"`
- [ ] 错误信息包含"授权码无效"
- [ ] 提案正常落档，WebUI 提案页面可以看到该提案
- [ ] 用户可以正常手动审批部署

---

### P2-5: 权限限制

**步骤**:
1. 创建一个授权码，只勾选「部署」权限（不勾选修改、撤回）
2. 用该授权码尝试需要修改权限的操作（如果有对应 MCP 工具）

**预期**:
- [ ] 部署操作正常
- [ ] 无权限的操作被拒绝，错误信息包含"没有 xxx 权限"

---

### P2-6: WebUI 页面导航

**步骤**:
1. 打开 WebUI
2. 查看左侧导航栏「管理」分组

**预期**:
- [ ] 「管理」分组中有「授权码」菜单项（在 Agent 管理和安全闸之间）
- [ ] 点击「授权码」进入授权码管理页面
- [ ] 页面标题为「部署授权码」
- [ ] 右上角有「创建授权码」按钮

## 回归测试

### R-1: 正常人工审批流程不受影响

**步骤**:
1. MCP 调用 `autoflow_deploy_raw`，**不传** deploy_token
2. 观察结果

**预期**:
- [ ] 返回结果中没有 `auto_deploy` 字段（或为 null）
- [ ] 提案正常落档
- [ ] WebUI 提案页面可以看到该提案
- [ ] 用户可以正常手动审批部署

---

### R-2: 现有 Tab 组织模式功能不受影响

**步骤**:
1. 切换 per_flow / single_tab / mixed 模式
2. 正常部署 flow

**预期**:
- [ ] 三种模式都正常工作
- [ ] 授权码自动部署也遵循当前 Tab 组织模式（或授权码绑定的 target_tab）

---

### R-3: 撤回功能不受影响

**步骤**:
1. 部署一个 flow
2. 在 WebUI 已部署页面撤回

**预期**:
- [ ] 撤回正常工作
- [ ] 节点精确删除，不影响其他 flow
