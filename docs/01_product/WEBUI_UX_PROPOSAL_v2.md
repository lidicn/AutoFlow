## 一、文案策略（v2 核心调整）

### v1 的问题
v1 走了"全面去技术化"路线，把 flow→自动化流程、子流程→功能模块、已部署→已安装、Link API→外部连接——这对 hassbian 用户是**降级**。他们天天在 NR 里拖 flow、写 subflow，看到"功能模块"反而要反应一下"这说的是 subflow 吗？"

### v2 策略：专业简洁，术语保留，特有概念加注

| 原则 | 说明 |
|---|---|
| **保留通用技术术语** | flow、tab、节点、实体、DSL、部署、子流程、NR、HA、MCP、API —— 用户都懂，不翻译 |
| **AutoFlow 特有概念首次出现加注释** | 安全闸、vhass 虚拟孪生、自愈闭环、逃逸开关、注册表漂移、Link API 桥接 —— 用副标题或 tooltip 解释 |
| **专业但不晦涩** | 像 HA/NR 官方文档的语气：精确、简洁、可操作，不用消费产品的"可爱化"语气 |
| **错误提示要可行动** | 不说"出错了"，说"部署失败：NR 连接超时，请检查 Node-RED 地址" |
| **不用 emoji 当主标识** | emoji 可作辅助装饰，但按钮/状态用文字+图标，不依赖 emoji 传义 |

## 五、UX 布局优化（v2 精选，不搞大工程）

### 5.1 顶栏按钮加文字标签

**问题**：🧪⚖♻️ 三个按钮只有 emoji + title，用户不点上去不知道干嘛。🧬 有"逃逸"文字但词不达意。

**方案**：全部加简短文字标签，顶栏空间足够（桌面端 200px 侧栏 + 内容区，顶栏右侧有充足空间）。

| 按钮 | 新显示 |

| ♻️ | ♻️ 自动修复 |

### 5.2 侧边导航分组

**问题**：16 项平铺，缺乏层次。

**方案**：用分隔线 + 组标题分组（组标题用 11px 灰色大写字母，不占太多空间）。

```
────────── 核心 ──────────
概览

已部署

诊断

────────── 系统 ──────────
设置

```

### 5.3 列表项加左侧状态色条

**问题**：提案/已部署列表项都是白底卡片，状态靠徽章区分，扫一眼不够快。

**方案**：列表项左侧加 3px 色条：
- 安全闸 PASS / 已部署正常 → 绿色 `--ok`
- 安全闸 FAIL → 红色 `--danger`
- 待审核 / 需人工审核 → 橙色 `--warn`
- 注册表漂移 → 红色虚线

### 5.4 空态加引导

**问题**：空态只有一行灰色文字，缺乏引导。

**方案**：空态加图标（SVG，不用 emoji）+ 引导文字 + 操作按钮。

示例（提案空态）：
```
[📋 图标]
还没有提案
Agent 提交 DSL 或 flow 后会出现在这里
[查看如何接入 Agent →]
```

### 5.5 按钮统一样式

**问题**：按钮高度/圆角/字号基本统一，但主按钮/次按钮/危险按钮的视觉权重可以更明确。

**方案**：
- 主按钮（primary）：实心主色 + 白字 + 圆角 10px + `--shadow-brand`
- 次按钮（default）：白底 + 灰色边框 + 深灰字
- 危险按钮（danger）：实心红色 + 白字
- 幽灵按钮（ghost）：透明底 + 灰字（仅顶栏/关闭按钮用）
- 统一高度 36px，padding 8px 14px，字号 14px

### 5.6 Toast 加类型区分

**问题**：所有 Toast 都是深灰底白字，不区分成功/失败。

**方案**：左侧加 3px 色条 + 图标：
- 成功 → 绿色 + ✓
- 错误 → 红色 + ✕
- 警告 → 橙色 + ⚠
- 信息 → 蓝色 + ℹ

### 5.7 统计卡片加图标

**问题**：概览页 4 个统计卡都是纯文字，缺乏视觉层次。

**方案**：每个统计卡左侧加一个圆形图标背景（主色浅底 + 主色图标），右侧数字+标签。

### 5.8 不做的改动

- 不改响应式断点（现有断点合理）
- 不改 PWA/manifest/sw.js
- 不改品牌 logo
- 不改帮助页结构（仅文案调整）
- 不改登录/账号模块（文案已经够技术向）

## 七、v1 → v2 关键决策变更汇总

| 决策点 | v1（去技术化） | v2（极客向） | 理由 |
|---|---|---|---|
| flow | 自动化流程 | flow（保留） | NR 用户天天用 |
| 子流程 | 功能模块 | 子流程（保留） | NR 标准术语 |
| 已部署 | 已安装 | 已部署（保留） | 部署是技术圈通用词 |
| Link API | 外部连接 | Link API（保留） | AutoFlow 特有概念，改名反而困惑 |
| MCP | 连接协议 | MCP（保留） | AI 技术圈标准 |
| DSL | 自动化规则 | DSL（保留） | AutoFlow 核心概念 |
| 身份识别码 | 接入密钥 | 接入令牌 | 比"识别码"更准确，比"密钥"更符合 token 语义 |
| 自愈闭环 | 自动修复 | 自动修复 | 保留 v1 改动，"自愈闭环"是内部隐喻 |
| 逃逸 | 高级模式 | 原生节点 | 直接说功能，不用隐喻 |
| 审计日志 | 操作日志 | 操作日志 | 更准确，审计有合规含义 |
| 配色 | 暖靛青+暖橙大改 | 蓝色微调 | 极客用户接受蓝色技术风 |
| 侧边导航 | 分组 | 分组 | 保留 v1 方案 |
| 顶栏按钮 | 收纳到下拉 | 加文字标签保留在顶栏 | 极客用户喜欢快捷访问，不喜欢多一层点击 |
