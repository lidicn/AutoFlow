## 三、幽灵类型 `merge` 的处置（缺陷 ④ 闭环）

`merge` 曾在 `RAW_NODE_ALLOWED` 中，但带外探针比对显示：

```
[GHOST]   merge                  <- 运行时查无此类型
[FAIL] 幽灵类型 1 个: ['merge']
```

- 1880 / 1990 **两个** NR 实例的 `GET /nodes` 均无 `merge`；Node-RED 核心从未提供该节点，合并职责由 `join` 承担。
- 后果不是「部署报错」而是**静默灾难**：部署接口返回 200，NR 日志打印
  `Waiting for missing types to be registered: - merge`，然后**整个 tab 拒绝启动**
  （该 tab 内所有节点全部失效，inject 触发返回 404）。
- 本轮处置：
  - `src/autoflow_gateway/dsl_engine.py` — 从 `RAW_NODE_ALLOWED` 移除，并留注释说明后果与回归入口。
  - `src/autoflow_gateway/gateway.py` — `_RECOGNIZED` 同步移除。
  - `capmatrix_build.py` 保留 `merge_node()` 工厂，但它**只会 `raise RuntimeError`**，防止后人误用。
  - 长期护栏：`capmatrix_probe_types.py` 每次运行都拿白名单 × 运行时注册表做全量比对，
    任何人再往白名单塞一个运行时不存在的类型，探针立刻红。

移除后复验：

```
禁止类型在运行时存在（应为真，证明是主动封杀）: ['exec', 'function']
[PASS] 白名单全部可用。
```

## 五、本轮定位的产品/环境缺陷

编号延续前序轮次（① – ③ 属 round1/2）。

| 编号 | 类别 | 现象 | 根因 | 处置 |
|---|---|---|---|---|
| ④ | **产品缺陷** | 白名单含幽灵类型 `merge`，用了整个 tab 不启动 | NR 核心无此类型 | 已从白名单移除 + 探针长期护栏 |
| ⑤ | **产品缺陷** | `server-state-changed` 节点静默不订阅、永不触发、不报错 | 生成器沿用旧版字段名（`entityId`/`entityIdType`/`output_initially`），现网 contrib 是 version=6：`entities:{entity[],substring[],regex[]}` + `outputInitially` | 新增 `ssc_node()` 工厂对齐现网 schema（含 `for`/`forType`/`forUnits`） |
| ⑥ | **产品缺陷** | `sort` 降序看似不排序 | `as_num` 是 **boolean**，传字符串 `"false"` 在 JS 里 truthy → 字符串数组全变 NaN 排回原序 | `as_num=bool(as_num)` |
| ⑦ | 测试设计 | `batch(count)` 分组数恒为 1 | 各组**复用同一 `parts.id`**，不能用 distinct(id) 计数；组边界靠 `parts.index` 归零 | 断言改 `index===0` 计数 |
| ⑧ | 环境策略 | SF1 夜间恒 FAIL，与「link out 断了」无法区分 | TTS 队列入口第一跳是 `time-range-switch(06:50-23:00)`，夜间消息在到达队列管理器前即被拦 | 加并行探针 link in（直接断言节点能力）+ 时段感知断言（静默窗要求「未登记」= 闸门正确） |
| ⑨ | 环境限制 | A2 恒 `on=>on` 假 FAIL | 载体实体（米家驱蚊器）设备侧不可控，REST toggle 后 34s 状态纹丝不动 | 换成实测 1s 内翻转的可控实体，并设计复位链保证 net-zero |
| ⑩ | 工具链 | 部署被拒：`link out 期望 1 个 output 却得 0 个 wires` | `nr_client` 结构 lint 要求 link out 恰有 1 个 wires 数组 | wires 写 `[[]]` 而非 `[]` |
| ⑪ | **产品缺陷** | ssc 输出的实体名恒为空，且不报错 | `outputProperties` 的 `valueType="entityId"` 是**非法值**，填了不报错但什么也不写 | 改取整个 `entity` 对象读 `.entity_id`，`eventData` 兜底 |
| ⑫ | 环境/常识陷阱 | N7/N8 websocket 环回失败，且**连状态事件都不发** | 容器是 **host 网络模式**（`docker port` 无映射），NR 直接在宿主 listen **1990**；`127.0.0.1:1880` 是**隔壁另一个 NR 实例**，那边没有 `/capm_ws` 路由 | ws client 指向 `ws://127.0.0.1:1990/capm_ws`；判定法：`docker inspect -f '{{.HostConfig.NetworkMode}}'` + `netstat` 看真实监听口 |

## 六、防「三层假象」自查

工单点名的三类假象，逐条对账：

1. **解析路径假象**（用例根本没被解析/执行，却不显示为失败）
   → `self_check()` 硬校验：断言节点**必须有入边**。教训来自 TR2——它有 fan 入口但断言节点悬空，
   于是永远不产出；join 收不齐时该用例不是 FAIL 而是**彻底消失**。现在悬空即构建期报错。
2. **skip 数假象**（跳过被算作通过）
   → 无 skip 机制。断言双写 flow context + 旁路 DUMP：缺席用例在总表里显式列为「未返回(超时/异常)」。
   总表尾行 `通过 73/73` 的分母来自用例清单长度，不是「已返回条数」。
3. **覆盖率假象**（master ∪ index 式的虚高覆盖）
   → 覆盖率不由生成器自报，而由**带外探针** `capmatrix_probe_types.py` 拿
   `dsl_engine.RAW_NODE_ALLOWED` × 目标 NR `GET /nodes` 真实注册表做交叉比对，
   幽灵类型直接判 FAIL（`merge` 就是这样被抓出来的）。

## 八、遗留与注意事项

- 本 tab 常驻会在宿主占用 **TCP 21801 / UDP 21802** 两个端口并开放 ws 路由 `/capm_ws`。
  重复部署时 `_purge()` 会先删旧 tab 再建新的，端口释放存在毫秒级窗口；
  若偶发 `EADDRINUSE`，重跑一次部署即可（节点状态会明示）。
- MQTT 用例一律 `retain=false`：retain=true 会在 broker 上留存消息污染其他订阅方，与 net-zero 纪律冲突。
- SF4/SF5 依赖 HA recorder 落库，SF4 特意延时 26s 起查（等本轮 A3/SS1 对灯的操作落库）。
- A4–A12 属「派发类」服务（无可读回实体），证据形式为**双路**：成功路带 rtt，
  错误路要求 HA 返回的结构化错误**回显本次载荷**——两者都能证明请求真的被 HA 处理过。
