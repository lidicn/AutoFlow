# AutoFlow 场景提示词库（投喂 deepseek++ 批量产 flow）

> 用法：在 deepseek++ 里先敲 `/autoflow`（编译器路径 / 原生手写路径 合一的单入口技能），
> 再**直接复制粘贴**下面任意一段场景描述即可。这些是**自然语言**，不含语法束缚——
> "怎么写"由 skill 负责（按你的身份能力自动走 编译器路径 / 原生手写路径），你只描述"想要什么"。
>
> 分级：⭐ 基础（能套模板）｜⭐⭐ 常见（单触发+条件/延时）｜⭐⭐⭐ 进阶（分支/多动作/播报）
> ｜⭐⭐⭐⭐ 复杂（多段链路/外部 HTTP/定时聚合，建议走原生手写路径）。
> 建议先用编译器路径把 ⭐~⭐⭐⭐ 跑顺，⭐⭐⭐⭐ 用原生手写路径探边界。

---

## A. 编译器路径推荐（/autoflow 单入口，稳、可自证）

### ⭐ 基础
1. 书房有人就把书房主灯打开，亮度大概 80%。
2. 卫生间检测到有人，自动开卫生间灯；人走了之后过一会儿自动关掉。
3. 玄关门一开，就把玄关灯点亮。
4. 每天晚上 22:30，把客厅的灯全部关掉。
5. 一进书房门，就用语音播报一句"欢迎回家"。

### ⭐⭐ 常见
6. 主卧室晚上有人起夜（检测到移动），只开一盏很暗的夜灯，白天不要触发。
7. 阳台光照低于某个值时打开阳台补光灯，天亮了就关掉。
8. 厨房检测到有人做饭（有人+时间在做饭点），把厨房灯和抽油烟机相关的灯打开。
9. 客厅电视打开时，自动把客厅主灯调暗到 30% 营造观影氛围。
10. 家里没人（所有人体传感器都无人）超过 10 分钟，关掉全屋不必要的灯。

### ⭐⭐⭐ 进阶（分支/播报/多动作）
11. 有人回到家开门时：如果是晚上就开灯并播报"欢迎回家"，如果是白天只播报不开灯。
12. 检测到书房有人且外面很热时，先开书房灯，再语音提醒"书房温度偏高，已为你留意"。
13. 早上 7 点：拉开窗帘、把卧室灯渐亮、并用一般音量播报今天的问候。
14. 门窗传感器检测到阳台门被打开且当前无人在家，用"警告"级别全屋播报提醒。
15. 有人进浴室：开灯、开排气；离开后延时 3 分钟关灯，排气再多开 5 分钟。

## B. 原生手写路径推荐（/autoflow 单入口，探索/非标/外部集成）

### ⭐⭐⭐ 进阶
16. 我想要一个每 30 分钟轮询一次天气 API，把结果存到一个变量，供别的流程用的 flow。
17. 做一个 HTTP 入口：外部 POST 一段文本进来，就触发全屋语音播报这段文本。
18. 收到 MQTT 某个主题的消息时，根据消息内容里的房间字段，去开对应房间的灯。

### ⭐⭐⭐⭐ 复杂（多段链路/多入口）
19. 一个"多入口天气分发"：既能被定时器每小时触发去拉彩云天气(GET)，也能被外部
    POST 豆包接口(带 headers 和 JSON body)触发，两条链路各自独立，结果都汇总打印到 debug。
20. 做一个语音指令路由：收到一段文本指令，用 switch 判断——含"开灯"就开客厅灯，
    含"关灯"就关客厅灯，其它指令走"未知指令"分支打印日志。
21. 早晚各一次，聚合家里所有传感器状态生成一份简报，通过 HTTP 发到我的 webhook。
22. 做一个防误触发的开门播报：门开后 2 秒内如果又检测到有人才播报，否则忽略
    （避免只是路过带门风导致误报）。

---

## C. 压力/边界测试（专门找网关的坑，原生手写路径）
23. 故意用很短的节点 id（n1、n2）和不带坐标写一个三节点的 inject→function→debug，
    看网关能不能自动补全并部署成功。
24. 写一个 HTTP Request 节点，body 是一个嵌套 JSON 对象，验证网关不会把 body 双层转义。
25. 一个 flow 里放两个独立触发链路（一个 inject、一个 http in），验证不会被错误 fan-in。

---

> 反馈闭环：无论编译器路径还是原生手写路径，网关都会把你每次产出的完整 flow JSON 留存在
> `data/flow_snapshots/<日期>/`；失败会记进 `data/raw_deploys.jsonl`。
> 这些语料就是"迭代编译器"的原料——哪类自然语言 deepseek++ 老写错，就补进模板/编译器。
