产品是什么

AutoFlow 网关是一座「桥」：它让你用自然语言指挥 AI Agent 去编写并部署 Home Assistant / Node-RED 的自动化 flow，同时用 安全闸 和 人工审核 守住真实电器的安全边界。核心闭环是：

① 配置 MCP 把 agent 接入网关 → ② Agent 编写 flow（DSL 或原生 flow）→ ③ 网关审核 / 部署（闸门 + 你点「部署到 NR」）→ ④ 真跑不通时，你跟 Agent 沟通，让它走自动修复自动修。

本手册依次讲清这四步，以及兜底的安全机制。建议第一次使用前通读，之后可按目录跳读。

一、接入 Agent（MCP 配置）

MCP（Model Context Protocol）是 agent 与网关对话的协议。每个 Agent 拿到一张「接入令牌」后，在它的 MCP 客户端里填好地址和令牌即可连上。

步骤

  1. 打开左侧 Agents 面板，填 名称（如 deepseek++）、权限级别（tier）、身份模式（mode），点「生成接入令牌」。
  2. 弹窗里会显示一次性接入令牌与连接信息，请立即复制保存（接入令牌仅显示这一次）。
  3. 在你的 Agent / MCP 客户端里按下方配置填写。

连接配置

服务器地址（端点，依身份模式而定）： 黑箱（仅 DSL）： http://<网关host>:8000/mcp 白箱（可自由部署）：http://<网关host>:8000/mcp-white 双箱（先白后黑）： http://<网关host>:8000/mcp-white 管理员（运维）： http://<网关host>:8000/mcp-admin 请求头： Authorization: Bearer <接入令牌>

身份模式（mode）怎么选

模式能做什么何时用
黑箱 black只提交 DSL，由编译器生成 flow，禁止 Function 节点常规场景自动化，最安全
白箱 white可直接写 raw flow（含原生节点）并部署需要原生节点 / 逃生舱场景
双箱 dual先白箱后黑箱，连 /mcp-white想灵活但保留 DSL 回落
管理员 admin运维专用，连 /mcp-admin网关维护，普通 agent 不用

权限级别（tier）

staging 练手 / 虚拟 HA，随便试； prod 真实环境，动真设备； sandbox 受限沙箱。

连不上时先核对：① 地址端口对不对（默认 8000）；② 接入令牌是否完整、有无多余空格；③ 该 agent 是否被「吊销」（吊销后连接会被拒）。

二、让 Agent 编写 flow

接入后，你用大白话给 agent 下指令（如「书房 PC 开机时，把书房显示器挂灯调到 60% 暖光」），agent 通过 MCP 工具把场景提交给网关。提交物分两类：

提交物来源网关判定含义
DSL 场景编译器编译编译产物·可信自动生成，无 Function 节点，可自动部署
原生 raw flowagent 手写手写·需审含原生节点，部署前必须人工审核

Agent 提交后，场景会出现在 提案 面板：

  • 能看到 闸门结果：闸门 PASS 或 闸门 FAIL；
  • 能看到 闸门断言（✅/❌ 逐条列出期望状态）；
  • 能看到 静态检查（原生 flow 的 lint error/warning、硬伤、逻辑不可达）；
  • 可信 DSL 标「可信·可自动部署」，原生 flow 标「需人工审核」。

你不必看懂 DSL 细节——看闸门 PASS/FAIL 和断言就够了。FAIL 时把页面上的报错原文转给 agent，让它改。

三、审核 / 撤回 Agent 编写的 flow

1）提案面板（部署前把关）

在 提案 面板对每个场景做决定：

  • 部署到 NR：闸门通过且你认可，点它把 flow 落到 Node-RED（可信 DSL 可一键；原生 raw 需你确认无误后部署）。
  • 拒绝：明显不对，打回给 agent 重做。
  • 归档 / 删除：暂时搁置或彻底移除提案。
  • 注册子流程：若是子流程类提案，点它写 NR 子流程实例 + 登记注册表，之后 Agent 可经 MCP 调用。

2）已部署面板（部署后撤回）

部署成功后，flow 出现在 已部署 面板，你可：

  • ▶ 触发：手动点火验证 flow 是否真跑通（等价于点一次 inject）。
  • 撤回：安全移除该 flow。只删网关自己写入的节点，保留你在该 tab 里自己的节点。

撤回有两种结果，会弹 toast 提示：

  • trimmed_tab：tab 里还有你自己的节点，只移除网关节点、保留你的节点；
  • deleted_tab：整个 tab 都是网关部署的，整 tab 删除。

若出现 注册表漂移：网关账本记着已部署，但 Node-RED 里已无该 flow_id（可能你手动删过 / 换了 NR 实例）。此时撤回只清账本、不碰 NR，属正常现象。

四、安全闸是什么、怎么用

安全闸 = 真实设备保护机制。网关能控制真实电器，误操作有现实后果（设备损坏、能耗、安全隐患）。安全闸让你预先声明「哪些设备 agent 不能乱动」，在 agent 的部署/操作触及这些设备时强制拦截或留痕。

使用步骤

  1. 打开 安全闸 面板，点「导入全部设备」：从 Home Assistant / Node-RED 拉取全屋实体目录（仅显式触发，不会随测试自动跑）。
  2. 在「添加保护」搜索框输入设备名 / 区域（如「书房灯」「客厅」「office」），点选设备加入保护。
  3. 给规则选 保护等级：
等级行为适用
Tier-0 需确认agent 触及即暂停等人工确认高价值 / 危险设备（空调、总闸、门锁）
Tier-1 放行放行但记操作日志低风险常调设备（夜灯、风扇）

原则：宁可先 Tier-0 把所有重要设备圈起来，再按需放宽到 Tier-1。去人审（自动修复）后，操作日志是你唯一可追溯来源，请在「设置 → 操作日志」里定期回看。

五、flow 不工作？跟 Agent 沟通 + 自动修复

第一步：你自己先验证

  • 到 已部署 面板点 ▶ 触发 手动点火；
  • 到 诊断 面板做 debug 回看，看 flow 真实输出（红色报错 / 空输出 / 节点数异常都算「没跑通」）；
  • 把看到的报错原文（debug 文本、断言失败项、异常节点）发给 agent。

第二步：让 agent 走自动修复

你只需对 agent 说「这个 flow 跑不通，走自动修复修一下」。Agent 会按下面循环自动调试：

inject 点火 → debug 回读 网关旁路订阅的 NR 输出 → 分析报错 → apply 修正 flow → 再点火验证 → 直到跑通。

为防止 Agent 陷入「修了又错、错了又修」的死循环，网关有 自愈预算：

  • 默认 最多 3 次自动修正尝试（按 (agent, flow) 计失败次数）；
  • 顶部 ♻️ 按钮可改这个上限；设为 0 即关闭自动修复（此时任何修正都回到人工审核）；
  • 预算用尽仍失败，Agent 会如实告诉你「已超重试上限，需你人工介入」，而不是偷偷假装成功。

关键认知：自愈预算是「纯失败次数计数」——它跟 flow 里有没有 inject 节点无关。有没有 inject 只影响「能不能自动点火验证」，不影响预算这道安全闸门本身。

六、inject 节点是自动修复必须的吗？（重点答疑）

结论：不是必须。下面分两层讲清。

1）自愈预算本身不依赖 inject

网关的失败计数保护（_selfheal_budget_check）是按 (agent, flow) 的失败次数计数的，完全不关心 flow 里有没有 inject 节点。所以即便没有 inject，预算机制照常生效，agent 也不会无限循环。

2）没有 inject 时，触发这一步会怎样

自动修复的「点火」入口在发现 flow 没有 inject 节点时，不会报错，而是返回：

{ "ok": true, "triggered": [], "warning": "该 flow 没有 inject 节点，无触发目标" }

即 triggered 为空、带一句警告。此时自动修复「分析 / 修正 / 验证」链条里，「自动点火验证」这一步没有目标。Agent 应当这样处置（按推荐顺序）：

  1. 补一个 inject 节点：最常见的修法，让 flow 可被自动点火；
  2. 改用 flow 已有的其他触发器：如 HA 状态变化事件、HTTP in、websocket 等——这些触发同样会产生 debug 帧；
  3. 如实告知你：若实在无法自动验证，Agent 应说「该 flow 没有可自动触发的入口，请你手动触发，或我给它加一个 inject」，而不是假装跑通。

而 debug 回读（autoflow_debug_read）读的是网关旁路订阅的 NR debug 事件流，对「任何产生的 debug 帧」都有效、与触发源无关——所以只要 flow 真被触发过（不管谁触发的），Agent 都能读到输出去做修正。

一句话总结：inject 不是自动修复的「开关」，只是「自动点火的便捷入口」。没有它，预算保护照常、debug 回读照常，只是 agent 得先解决「怎么触发这个 flow」才能自动验证——要么加 inject，要么用别的触发器，要么请你手动触发。

七、补充：接入令牌安全 / 顶部开关 / 子流程 / 操作日志

接入令牌安全

  • 接入令牌仅生成时显示一次，请妥善保存；
  • 重置接入令牌：旧码立即失效，生成新码（仍只显示一次）；
  • 吊销：Agent 无法再连网关（记录保留可恢复）；删除：彻底移除、不可恢复；
  • 怀疑泄露 → 直接「重置接入令牌」即可废掉旧码。

顶部开关（topbar）

按钮作用
🔑设置 WebUI 访问令牌
🧪DSL 验证任务池开关（关闭后 agent 的 DSL 调用被拒）
🧬 逃逸原生节点逃逸开关（中风险逃生舱，可随时关）
⚖部署策略（compiler_auto 下编译产物标「可信」可自动部署，raw 仍须人审）
♻️自动修复最大重试次数（默认 3，0 = 关闭）

子流程提案

agent 可提交「子流程」类提案。你在提案面板点 注册子流程 后：写 NR 子流程实例 + 登记子流程注册表，之后 agent 即可经 MCP 调用该子流程（如历史查询、Bark 推送等通用能力）。

操作日志

在 设置 → 操作日志 查看所有部署 / 应用修正的留痕。去人审（自动修复）后，这是唯一可追溯来源，建议定期回看。

核心概念详解

AutoFlow 涉及一些特有概念，这里逐一解释原理和作用。

DSL（领域特定语言）

DSL 是 AutoFlow 定义的一种结构化场景描述语言，比原生 Node-RED flow JSON 更简洁、更安全。Agent 提交 DSL 后，网关的编译器会将其转换为标准 NR flow 节点。

编译器生成的 flow 不含 Function 节点（无法执行任意 JS 代码），因此被标记为「编译产物·可信」，可免人工审核直接部署。这是 DSL 模式比 raw flow 模式更安全的根本原因。

安全闸（Safety Gate）

安全闸是 AutoFlow 的真实设备保护机制。在 flow 部署到 Node-RED 之前，网关会检查 flow 中操作的设备是否在受保护列表中：

  • Tier-0（需确认）：触及即暂停，等人工确认后才能继续
  • Tier-1（放行+审计）：允许操作，但记录到操作日志

安全闸的检查结果以「断言」形式展示（✅/❌ 逐条列出预期状态），你不必看懂 DSL，看断言就知道 flow 会操作哪些设备。

vhass（虚拟孪生重放）

vhass 是 AutoFlow 的虚拟环境测试能力。它可以在不触碰真实设备的情况下，模拟 Home Assistant 环境来验证 flow 的行为。

当 flow 部署到 staging（测试环境）时，网关会先在虚拟环境中重放 flow 的执行过程，检查预期状态是否满足。只有虚拟验证通过后，才允许部署到 prod（真实环境）。

这相当于给自动化流程加了一道「彩排」——先在虚拟舞台上演一遍，确认没问题再正式演出。

自动修复（原称自愈闭环）

自动修复是 AutoFlow 的核心能力：当已部署的 flow 不工作时，Agent 可以自动调试并修复，无需你手动排查。

修复循环：inject 点火 → debug 回读（网关旁路订阅 NR 的 debug 事件流）→ 分析报错 → apply 修正 flow → 再点火验证 → 直到跑通。

为防止死循环，网关有自动修复预算（默认最多 3 次重试，按 Agent+flow 计失败次数）。预算用尽后 Agent 会如实告知「需人工介入」，不会假装成功。

Link API（HTTP 桥接）

Link API 是 AutoFlow 的外部 HTTP 服务桥接能力，让 flow 可以调用外部 API 或接收外部 webhook。

两种模式：

  • link out 推送：把 flow 的输出推送到外部 HTTP 端点（如第三方 API、webhook）
  • http_api 内联：网关内置 HTTP 接口，不生成 NR 节点，直接由网关处理请求

Link API 安装后会合并到 Node-RED 的「AutoFlow API」tab 中，增量更新不重复创建节点。

子流程注册表（Subflow Registry）

子流程注册表是 AutoFlow 管理可复用 NR 子流程的目录。注册后的子流程，Agent 可以通过 MCP 直接调用（在 DSL 中写「调用子流程: 名称(参数)」）。

子流程分两类：

  • 内置（managed）：AutoFlow 自带的子流程（如 Bark 推送），网关负责安装和更新
  • 已导入（imported）：你从 Node-RED 导入的自定义子流程，网关只登记不修改 NR 实例

删除内置子流程会同时删除 NR 实例；删除已导入子流程只从注册表移除，NR 上的子流程保持原样。

注册表漂移（Registry Drift）

注册表漂移指网关的注册表记录着某个 flow「已部署」，但 Node-RED 里已经找不到这个 flow_id 了。

常见原因：你手动在 NR 里删除了该 flow，或者更换了 Node-RED 实例。这不是错误，而是记录不一致。

处理方法：点击「撤回」，网关会只清理注册表、不碰 Node-RED（因为 flow 已经不在了）。

八、常见问题 FAQ

  • agent 连不上网关？ 核对端点地址（黑/白箱别填反）、接入令牌完整无空格、该 agent 未被吊销。
  • 提案显示「需人工审核」但我想自动化？ 那是原生 raw flow（含原生节点），按设计必须人审；改用 DSL 场景可走「可信·自动部署」。
  • 撤回会误删我自己的节点吗？ 不会。只删网关写入的节点，你的节点保留（见 trimmed_tab / deleted_tab 提示）。
  • 自动修复一直修不好？ 预算（默认 3）用尽后 agent 会交回人工；你也可把 ♻️ 调到更大，或自己看 debug 把报错发给 agent。
  • flow 没有 inject 还能自愈吗？ 能，预算照常；只是 agent 需先解决「怎么触发」——加 inject、用别的触发器、或请你手动触发（详见第六章）。

仍有疑问？把现象贴给 agent，或在「笔记」里记下待办，下次让 agent 帮你查。

首次使用 · 风险须知

AutoFlow 可控制 真实电器与设备。误操作可能造成现实世界后果（设备损坏、能耗、安全隐患）。

继续使用即表示你已理解并接受这一风险，并确认你对此运行环境拥有合法控制权。
